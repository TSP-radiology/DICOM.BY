# Заявление о соответствии стандарту DICOM (`DICOM Conformance Statement`) — DICOM.BY `0.9.4`

- **Стандарт оформления:** `NEMA DICOM PS3.2` (Conformance) и `DICOM PS3.15 2026d` (Security and System Management Profiles, Annex E).
- **Продукт:** `DICOM.BY` (`Desktop Community Freeware 0.9.4` и `Gateway Pro 0.9.4`).
- **Implementation Class UID:** `2.25.3141592653589793238462643383279502884`
- **Implementation Version Name:** `DICOMANON_0_9_4`
- **Дата редакции:** `2026-11-27`

---

## 1. Обзор соответствия (`Conformance Overview`)

Программный комплекс **DICOM.BY** представляет собой локальный детерминированный узел деидентификации объектов `DICOM Part 10` (`PS3.10`) и сетевой шлюз маршрутизации медицинских исследований (`PACS ↔ AI / Научные регистры / Консилиумы`), работающий внутри периметра медицинской организации без передачи исходных персональных данных пациентов во внешние облачные сервисы.

Каждая операция обработки подчиняется формальному автомату четырёх исходов (`Fail-Closed`):
- **`PROVEN`** — допустим исключительно для объектов без пиксельного канала (`Enhanced SR`, `Comprehensive SR`), в которых все атрибуты заголовка и элементы дерева содержимого проверены полным детерминированным перебором;
- **`SCREENED`** — метаданные обработаны по профилю `PS3.15 Annex E`, а пиксельный канал проверен детектором вшитого текста (с обязательной встроенной оговоркой в `(0012,0063) DeidentificationMethod`);
- **`REVIEW`** — автоматический выпуск запрещён; объект изолируется исключительно в локальном каталоге карантина `_quarantine/` с установкой `(0012,0062) PatientIdentityRemoved = NO`;
- **`REFUSED`** — объект не принадлежит допущенному множеству `standard/admission_v7.json` либо нарушает структурные инварианты безопасности; выходной DICOM-файл не создаётся, формируется подписанная квитанция отказа `.refused.json`.

## 4. Соответствие профилю конфиденциальности `DICOM PS3.15 Annex E`

### 4.1. Заявленный профиль и опции (`CID 7050` в `(0012,0064)`)

| Код `DCM` | Наименование профиля / опции `PS3.15` | Статус и условие записи в `(0012,0064)` |
|---|---|---|
| `113100` | `Basic Application Confidentiality Profile` | **Обязателен всегда** |
| `113101` | `Clean Pixel Data Option` | Записывается при фактическом маскировании вшитых аннотаций (`lines_masked > 0`) |
| `113104` | `Clean Structured Content Option` | Записывается при полной очистке дерева содержимого `SR` (`--clean-sr` / `--clean-structured-content`) |

### 4.2. Семантика действий таблицы `E.1-1` и правило «закрытого мира»

- **`X` (Remove):** полное удаление атрибута из набора данных и всех вложенных `SQ`;
- **`Z` (Zero / Empty):** замена пустым значением нулевой длины (для `PatientID` и `PatientName` формируется криптографический псевдоним `PS-<Base32(80 бит HMAC-SHA-256)>`);
- **`D` (Dummy):** замена безопасной константой типа `VR` (либо сдвинутой датой при `113107` / перегенерированным `UID`);
- **`U` (Replace UID):** детерминированная замена `UID` на `2.25.<128-bit decimal HMAC-SHA-256(key, "UID|" + orig_uid)>` с полным сохранением ссылочной целостности между сериями, кадрами отсчёта (`FrameOfReferenceUID`) и структурированными отчётами `SR`; стандартные `UID` реестра `DICOM` сохраняются неизменными;
- **`C` (Clean):** очистка содержимого согласно типу атрибута и активным опциям;
- **`K` (Keep):** сохранение после проверки значения судьёй типов и отсутствия совпадений с исходными ПДн объекта (`Echo`);
- **Атрибуты вне таблицы `E.1-1` (`Closed-World Policy`):** любой публичный атрибут вне `annex_e.json` проверяется по открытому правилу [`standard/attribute_policy_v1.json`](../standard/attribute_policy_v1.json) (`PN/UR → X`, `DA/DT → C/X`, нестандартные `UI → U`, неразрешённые текстовые теги `→ X`, неизвестные публичные или неразрешённые бинарные теги `→ REFUSED`).
- **Контейнер `DICOM Part 10`:** 128-байтовая преамбула файла всегда зануляется (`0x00 * 128`), а заголовок `File Meta Information (0002,xxxx)` пересобирается строго по белому списку `(0002,0000/0001/0002/0003/0010/0012/0013)` без переноса `SourceApplicationEntityTitle` и приватных полей заголовка.

### 4.3. Поддержка кодировок (`SpecificCharacterSet`)

Поддерживается чтение и согласованная проверка `ASCII`, `ISO_IR 192` (`UTF-8`), `ISO_IR 100` (`Latin-1`), `ISO_IR 144` (`Cyrillic`) и китайских кодировок `GB18030 / GBK / GB2312 / ISO 2022 IR 58` (с транскодированием очищенных отчётов `SR` в `ISO_IR 192`). Наборы данных с противоречивым `SpecificCharacterSet` во вложенных `SQ` отклоняются (`REFUSED`), а с неподдерживаемой кодировкой текста `SR` направляются в карантин (`REVIEW`).

## 5. Гарантии атомарности, отказоустойчивости и многопоточности

1. **Защита от устаревших и частично записанных файлов (`RED-2 №5 / №11`):** перед обработкой удаляются все 5 возможных артефактов предыдущего запуска (`out.dcm`, `out.dcm.deid.json`, `out.dcm.refused.json`, `_quarantine/out.dcm`, `_quarantine/out.dcm.deid.json`). Если старый файл заблокирован сторонним процессом, возбуждается фатальная ошибка `StaleOutput` (исключая ситуацию, когда при отказе на диске остаётся прежний файл).
2. **Атомарная запись и самопроверка:** сериализация выполняется во временный файл `.<name>.<ns>_<seq>.tmp` с последующим контрольным перечитыванием `DICOM Part 10` парсером, проверкой нулевой преамбулы и соответствия `(0012,0062)`/`(0012,0063)` назначенному исходу до атомарного `rename` в целевой путь. При прерывании процесса, нехватке места на диске или исключении `.tmp`-файл удаляется, выходной объект не публикуется.
3. **Побайтовый многопоточный детерминизм:** параллельный запуск `--jobs 1` и `--jobs N` при флаге `--reproducible` порождает побайтово идентичные (`SHA-256`) выходные файлы `.dcm` и канонические тела сертификатов `.deid.json`.

## 6. Явные границы применимости (`Explicit Scope Boundaries`)

- **3D-реконструкция поверхности лица (`3D Cranial Defacing`):** в версии `0.9.4` геометрическая модификация вокселей кожи лица на тонкосрезных сериях КТ/МРТ головы **не выполняется**; при передаче нейровизуализационных выборок в полностью открытые публичные репозитории исследователь должен применять профильный регламент допуска.
- **Клиническая квалификация:** `DICOM.BY` является средством защиты информации и подготовки деидентифицированных данных и не заменяет клиническое решение врача-рентгенолога; исход `SCREENED` отражает статистически верифицированную очистку детектором, а не математическое доказательство отсутствия произвольных графических артефактов.
