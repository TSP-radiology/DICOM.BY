# Политика безопасности / Security Policy — DICOM.BY

## Принципы безопасности

1. **100% автономная обработка снимков:** вся деидентификация заголовков (`DICOM PS 3.15`) и очистка впечатанного текста в пикселях (`ONNX Runtime OCR`) выполняются локально на компьютере пользователя. Снимки и метаданные пациентов никогда не отправляются на внешние серверы.
2. **Конфиденциальность по умолчанию (З9):**
   - Выходная папка создаётся с нейтральным именем `Обезличено_YYYY-MM-DD_HH-mm-ss` и никогда не наследует имя исходной папки (которое может содержать ФИО пациента).
   - Публичный файл `ОТЧЁТ.txt` и экспортный `.zip`-архив содержат только обезличенные сводки и очищенные изображения — без исходных путей и имён файлов.
3. **Защита ключей и офлайн-активация:**
   - Ключ псевдонимизации учреждения автоматически защищается через **Windows DPAPI** (`clinic.dpapi`).
   - Офлайн-активация Desktop `0.4.3+` проверяет **Ed25519**-подпись регистрационного ключа `DICOMBY-1....` локально встроенным публичным ключом без сетевых обращений.
4. **Криптографическая защита цепочки обновлений и доказательств (`0.4.3+`):**
   - Клиент загружает манифест строго по HTTPS с `https://dicom.by/updates/windows-x64.json`, проверяет **Ed25519**-подпись (`signature_ed25519`) закреплённым в бинарнике публичным ключом (с защитой от отката версий), разрешает скачивание только с `https://dicom.by/` и сверяет **SHA-256** установщика через Windows CNG (`BCrypt`) до запуска.
   - Реестр доказательств [`RELEASE_MANIFEST.json`](RELEASE_MANIFEST.json) также подписан **Ed25519** и проверяется открытым верификатором [`verify/dicom_by_verify.py`](verify/dicom_by_verify.py).
   - Автопроверку обновлений можно отключить в окне «Обновления» для полностью изолированных сетей.

---

> [!CAUTION]
> **НИКОГДА не прикрепляйте реальные файлы DICOM пациентов или неотредактированные скриншоты с ФИО к публичным GitHub Issues или Pull Requests.**
> Для отчётов об ошибках используйте обезличенные тестовые срезы (например, из открытых коллекций TCIA) либо прикладывайте только техническое описание (модальность, `SOPClassUID`, текст ошибки без личных данных).

## Как сообщить об уязвимости

Если вы обнаружили проблему безопасности, ошибку утечки метаданных/пикселей или проблему в цепочке обновлений:
- Пожалуйста, **не публикуйте** детали в публичном Issue до согласования исправления.
- Свяжитесь с командой через форму контактов на **https://dicom.by/** с темой `[SECURITY] DICOM.BY`.
- Укажите версию программы (`VERSION.json`), шаги воспроизведения и при необходимости синтетический воспроизводящий пример без реальных данных пациентов.
